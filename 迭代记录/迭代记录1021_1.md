## 问题诊断与执行方案

### 问题 1：删除 install 包失败（`name '_prune_backups' is not defined`）

**根因**：`backend/routers/scripts.py:923` 调用了 `_prune_backups()`，该函数定义在 `backend/core/utils.py:482`。scripts.py 顶部通过 `from .common import *` 间接依赖 common.py 的导入，但 Python 的 `import *` **默认不会导入下划线开头的名字**（文件第 5 行已有同样原因的先例：显式补导了 `_memory_cache`），所以 `_prune_backups` 在 scripts.py 命名空间里不存在，删除版本目录时直接抛 NameError，被全局异常处理器兜底成"删除失败"。

**修复**：在 `scripts.py` 顶部显式导入：
```python
from core.utils import _prune_backups  # noqa: F401
```
（common.py:76 本身已导入它，其余 8 个路由文件不受影响。）

### 问题 2：不展示生成详情，只保留 📦 挂载路径

**位置**：`frontend/js/sj_script.js:3033-3036`，生成成功后循环渲染了 17 行 `📄 脚本 → 容器 (DOMAIN_ID=...)`（即截图红框部分）。

**修复**：删除该详情循环，仅保留"✅ 已生成 N 个脚本"和"📦 挂载路径"两行（warnings 端口冲突提示保留）。后端 `generated` 数组不动，改动面最小。

### 问题 3：排除 simulation_launch + 脚本按 sn 序号排序

**现状**：
- `script_generator.py` 目前把 `simulation_launch` 当作"配额豁免"车辆**照常生成脚本**（`QUOTA_EXEMPT_BASES`，第 29 行），所以磁盘上多出一个 `start_docker_ros2_simulation_launch__*.sh`。
- `get_launch_files()`（第 398 行）用 `os.listdir()` 取文件，**顺序不确定**；后续索引（ROS_DOMAIN_ID / VNC / Web 端口）按这个随机顺序顺序分配，脚本列表接口 `/api/scripts/list`（scripts.py:1672）同样是无序的。

**修复**：
1. `get_launch_files()` 扫描后直接过滤掉基名为 `simulation_launch` 的文件（连脚本都不生成），同时 `/api/scripts/launch-files` 扫描接口（scripts.py:17）保持一致过滤，避免前端"扫描预览"里还看到它。
2. 对 launch 文件按基名做**自然排序**（提取名称中的数字比较，`fz_c50 < fz_c51 < … < fz_c65`，兼容将来出现个位数编号），保证索引/端口随 sn 序号递增分配。
3. `/api/scripts/list` 返回前对脚本名同样自然排序，使"启动车辆"列表从小到大展示。
4. `QUOTA_EXEMPT_BASES` 相关豁免逻辑保留（无害，且旧脚本统计仍需识别），但新生成流程不再产出该脚本。

### 问题 4：可视化（原生 RVIZ）启动失败

**根因**：日志 `~/ros2_web/log/app.log` 实锤——`全局异常: name '_maximize_rviz' is not defined`。`backend/routers/visualization.py:475/478` 调用了 `_maximize_rviz()`，同文件 453 行还用了 `_resolve_rviz_config()`，二者都定义在 `core/utils.py`，但 visualization.py 只有 `from .common import *`，下划线函数导不进来，与问题 1 同源。VNC 路径不触发这两个函数所以正常，一点"原生 RVIZ"就 500。

**修复**：在 `visualization.py` 顶部显式导入：
```python
from core.utils import _resolve_rviz_config, _maximize_rviz  # noqa: F401
```
