一、系统架构总览

系统采用前后端分离架构。后端基于 FastAPI 提供 REST API 与 WebSocket，封装 Docker、ROS2 与系统资源的调用；前端为纯静态站点，通过 apiGet / apiPost 封装访问后端。鉴权使用 JWT，数据库支持 JSON 文件与 Supabase 两种适配器，可按配置切换。

二、后端目录结构与职责

后端代码位于 backend/ 目录，遵循四层分离原则。

表 2-1　后端目录职责
路径职责关键文件
app.py入口，创建应用、注册中间件、挂载路由与静态文件app.py
core/配置、常量、安全、工具、缓存、中间件、工作空间config.py、constants.py、security.py、utils.py、workspace.py
database/数据库适配器，支持 JSON 与 Supabasejson_db.py、supabase_db.py、__init__.py
services/业务服务，封装 Docker、脚本生成、监控等docker_manager.py、script_generator.py、system_monitor.py、traffic_light.py
routers/统一 API 路由（可按领域拆分）api.py
deps.py依赖注入：当前用户、权限校验deps.py
models.pyPydantic 数据模型models.py
logger.py统一日志配置logger.py

2.1 core 层要点

  • config.py：运行时配置加载与热保存，配置文件为 config.json。
  • constants.py：集中常量（端口、路径、权限点、可视化配置、缓存与 WebSocket 客户端容器等）。
  • security.py：密码哈希、JWT 签发与校验、命令清洗、速率限制器。
  • workspace.py：用户工作空间路径校验与创建，支撑多用户资源隔离。

2.2 services 层要点

  • DockerManager：封装 docker ps / inspect / kill / update / exec 等，统一带 sudo 前缀（DOCKER_PREFIX）。
  • SystemMonitor：采集 CPU、内存、GPU（nvidia-smi）与进程列表。
  • ROS2ScriptGenerator：依据 launch 文件生成启动脚本。
  • TrafficLightSender / TimerTrafficLightSender：红绿灯模拟的云端联动与计时模式。

三、前端结构

前端位于 frontend/，无构建步骤，直接由后端挂载为静态文件。

所有 API 统一注册于 routers/api.py，前缀 /api。下表按领域列出主要端点。

注意：容器列表接口返回字段包含 started_at（运行中容器的 Docker State.StartedAt，ISO8601）；停止容器不返回该字段，前端据此归零运行时长。新增依赖此时长的功能时，应统一从该字段取值，不得改用客户端时间。

五、WebSocket 通信

系统通过 WebSocket 实现终端、实时日志与消息推送。连接客户端集中维护于 core/constants.ws_clients。鉴权时 Token 通过查询参数或首条消息传递，连接建立后绑定到用户上下文。

  • 终端：/ws/terminal/{container}，前端 terminal.js 负责收发。
  • 实时日志：流式推送 docker logs -f 输出。
  • 广播日志：broadcast_log 工具函数向全部在线客户端推送系统消息。

六、数据库适配层

database/ 提供统一接口 db，底层可切换 JSON 文件或 Supabase。

适配器适用场景存储
json_db.py单机、轻量、无外部依赖data/data.json、data/audit_logs.json

七、安全机制

  • JWT 鉴权：HS256，默认 1 天有效期，记住我可延至 7/15/30 天。
  • 密码哈希：bcrypt，轮数可配（默认 12）。
  • 速率限制：基于 slowapi，登录注册默认 5 次 / 分钟。
  • 命令清洗：sanitize_command 对容器内执行命令做白名单过滤（可配）。
  • 权限校验：require_permission / require_admin 依赖注入。
  • 审计日志：登录、容器操作、用户管理等写入审计库，可查询与清理。
  • 资源隔离：普通用户仅可见与操作自有资源，_check_container_access 校验归属。
警告：修改安全相关逻辑（JWT 密钥、命令白名单、权限点）须充分回归测试，避免引入越权或命令注入风险。

八、二次开发规范

8.1 新增 API

  1. 在 routers/api.py 中新增路由函数，使用 @router.get/post 装饰器。
  2. 按需注入 get_current_user / require_permission / require_admin。
  3. 业务逻辑放入 services/ 对应类，保持路由层轻量。
  4. 涉及配置的项写入 config.json 与 core/constants.py。
  5. 关键操作写入审计日志（db.add_audit_log）。

8.2 新增前端面板

  1. 在 index.html 增加 <div class="panel" id="panel-xxx">。
  2. 在导航栏增加对应 nav-item，data-panel 指向新面板。
  3. 逻辑写入 sj_script.js，复用 apiGet/apiPost 与 showToast。
  4. 需要权限控制的按钮加 admin-only 类或运行时判断 hasPermission。

8.3 编码约定

  • Python 遵循 PEP 8，类型注解齐全；前端兼容老浏览器，使用 ES5 兼容写法（var、函数表达式）。
  • 新增常量集中到 constants.py，避免散落硬编码。
  • 外部命令统一经 DockerManager.run_cmd，带超时与错误处理。
  • 涉及时间的展示一律以后端权威时间为准，前端不得自维护本地时钟态。

九、部署与运维

部署脚本 deploy.py 支持 --skip-system / --skip-deps / --only-deps 参数，可批量检查并安装依赖、生成 systemd 服务。依赖清单见 redame/requirements.txt。

  • 服务默认监听 0.0.0.0:8875，CORS 通过 config.json 配置。
  • 日志文件 audit.log 与 data/audit_logs.json 按需轮转。
  • 升级时优先在测试环境验证，确认 API 兼容后再推生产。
